Deviations from the prompt and why:
- Node: this machine has v22.23.4 (not 24), so hsdeploy supports Node 22.2 or newer.
- Global install: a symlink install (`npm install -g ./tools/hsdeploy`) failed here; installed from a packed copy as package `hsdeploy-cli` (command `hsdeploy`). It left a broken link folder I could not remove (see owner actions).
- Image removal uses `dockerImage.removeImage` by id plus an ssh fallback, not Dokploy's global cleanup (`settings.cleanUnusedImages`), because that would also delete cached base images.
- Init flag is `--env-path` (Node intercepts `--env-file`). `trust` needs an interactive terminal (found by the security review).
- `/plan-eng-review` and `/review` were condensed chat-only runs; the `/qa` skill was not run (the apps are torn down by design), replaced by the two end-to-end runs and 16 CLI probes; `/cso` ran static and partial. Details in `docs/step-0.3-report.md` section 5.
- `.tmp/` was NOT emptied at the end: a built-in safety check blocked the removal command (it could not resolve the glob), so the sample apps, their node_modules and the packed tarball are still in the git-ignored `.tmp/`; the removal is left to the owner.
- Server-side nixpacks failed after 18.2 minutes, so there is no successful nixpacks timing; the failure and its resource use are recorded.
- The first E2E runs failed on real Dokploy behavior my unit tests had not modelled (eight fixes, listed in the report); the evidence files describe the final, clean runs.
